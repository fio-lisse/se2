Groepswerk (50%, gezamenlijk)

StartOp koersSterk
Werking15 punten
Laat in de demo een bruikbare stap van de gekozen klanttaak zien. Die stap geeft met voorbeeldinvoer een juiste tussenuitkomst. Een ander kan de hele klanttaak in de demo uitvoeren. Bij gewone invoer klopt de uitkomst. Bij Backend loopt de vraag via de regel en de database naar het antwoord en blijft een wijziging bewaard. De README kan de weg naar de demo wijzen. Laat in de demo ook zien wat er gebeurt bij een lastig geval. De reactie klopt en gegevens die gelijk moeten blijven, blijven gelijk.
Ontwerp10 punten
In Issue D (Klantvraag en ontwerp) staat welke taak de klant wil uitvoeren. Het eerste ontwerpschema toont een keuze voor die taak. In het schema in Issue D staan de invoer, de gegevens, de beslisregel en de verwachte uitkomsten van een gewone en een lastige situatie. Jullie leggen uit waarom jullie deze aanpak kiezen. Een link in de README helpt om het schema terug te vinden. Vergelijk in Issue D twee haalbare oplossingen voor dezelfde klantwens. Gebruik bij beide oplossingen dezelfde gewone en lastige situatie. Leg uit waarom jullie keuze beter past bij wat de klant nodig heeft.
Professioneel werken10 punten
In de README staan een herkenbare productnaam en links naar het werk. In de code is aan bestandsnamen of functienamen te zien waar het gemaakte onderdeel staat. De README vertelt wat het product doet en hoe je het opent. Bestanden of functies hebben duidelijke taken. In de commits is terug te vinden wat er aan de gekozen functie is gewijzigd. Een ander kan met de README het product zelfstandig openen en gebruiken. Uit de code en de commits blijkt waar een gerichte aanpassing thuishoort en welke andere onderdelen daarbij gelijk kunnen blijven. Een verwijzing in Issue M kan helpen die keuze terug te vinden.
Testen en verbeteren10 punten
Bij Issue E (Bouw en eerste tests) staat één uitgevoerde test met invoer, verwachting en echte uitkomst. Naar een verwachting in het ontwerpschema mag je verwijzen. In Issue E staan de eerste uitkomsten van een gewone en een lastige situatie. In Issue I staat welke verbetering jullie op basis van die uitkomsten hebben uitgevoerd. De wijziging is zichtbaar in de code of de demo. Bij Backend is ook één bewerking zonder scherm getest. In Issue I staan de nieuwe uitkomsten van beide situaties. Jullie gebruiken dezelfde beginstand als bij de eerste tests in Issue E. Vergelijk de uitkomsten en leg uit wat aantoonbaar beter werkt. Een bestaande Actions-run kan de uitkomsten ondersteunen.
Klantwaarde5 punten
In Issue D (Klantvraag en ontwerp) staat voor welke mogelijke klant jullie werken, bij welke taak die vastloopt en wat het concrete probleem is. In Issue D leggen jullie uit welk voordeel de functie oplevert voor die klant. In de demo is bij dezelfde taak te zien hoe de oplossing het probleem kleiner maakt. In Issue D maken jullie aannemelijk wie waarvoor zou betalen en waarom het voordeel die betaling de moeite waard kan maken. Benoem wat nog een aanname is. Een prijs of verkoop is niet nodig.

Mondeling (50%, individueel)

StartOp koersSterk
Eigen bijdrage20 punten
In Issue M (Uitleg en samenwerking) verwijs je naar bestaand werk, zoals een Issue, commit of gemaakt onderdeel. Tijdens het mondeling wijs je aan wat jij deed. Tijdens het mondeling wijs je je eigen werk aan en leg je uit wat jij deed, welke keuze je maakte en wat het resultaat was. Een Issue of commit kan je uitleg ondersteunen. Tijdens het mondeling laat je met eigen werk, zoals een Issue of commit, zien waar je initiatief nam en welk probleem je zelfstandig oploste. Leg uit wat het effect van jouw aanpak was.
Technisch begrip20 punten
Tijdens het mondeling wijs je in de code of het product een onderdeel aan en leg je uit wat het doet. De demo kan laten zien wat je bedoelt. Tijdens het mondeling volg je in de code hoe de invoer via de gegevens en de regel tot de uitkomst leidt. Iedereen krijgt dezelfde technische basisvragen. Een verwijzing in Issue M kan helpen de code terug te vinden. Tijdens het mondeling voorspel je wat er bij nieuwe invoer gebeurt. Wijs in de code de regel en gegevens aan die verklaren waarom die uitkomst volgt.
Reflectie en samenwerking10 punten
In Issue M (Uitleg en samenwerking) beschrijf je een concreet moment waarop je met een teamgenoot samenwerkte. Je kunt verwijzen naar werk dat er al staat. Tijdens het mondeling wijs je een bestaand voorbeeld aan. Leg uit wat een teamgenoot inbracht, wat jij daarmee deed en wat dat opleverde. Een bijdrage in Issue E kan je uitleg ondersteunen. Tijdens het mondeling leg je uit welk effect de samenwerking had. Noem een gerichte volgende stap en leg uit waarom die past bij het voorbeeld. Een verbetering in Issue I kan je uitleg ondersteunen.

Deadlines en punten

Op 30 november vult het team D in. Op 4 december staan de eerste tests in E. Uiterlijk 8 december om 16.00 uur staan verbetering en hertests in I en levert Manager één team-README-link in via het eindformulier #3. Het mondeling is van 10 tot 17 december en wordt voorbereid in M.
